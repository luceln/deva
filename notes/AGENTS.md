# Agent Notes

这里的 note 是**决策记录**：一条 note 记一次「为什么这样做」的定论，不是过程流水账。

## note 必须含四样

1. **为什么这样做** —— 结论背后的理由；没有理由的结论半年后没人敢改
2. **考虑过哪些替代方案** —— 至少一条被否掉的，连同否掉的原因
3. **后果是什么** —— 这个决定换来了什么、牺牲了什么、留下了什么债
4. **怎么验证** —— 哪条命令 / 哪个观察能证明它成立，或者证明它没做到

缺任一项的，不是 note，是备忘。

## 新增即取代检查（核心规则）

**每新建一条 note，必须先在 `proposed/` 和 `implemented/` 里搜有没有讲同一件事的旧 note**，搜到就按下面分类，**不许不分类直接新建**：

| 关系 | 怎么处理 |
| --- | --- |
| **完全取代**（旧 note 的结论已整体作废） | 新 note 里写明「取代 `<旧文件名>`」；把旧 note 移进 `archived/` |
| **部分取代**（只改了一部分结论） | 新 note 里写明「部分取代 `<旧文件名>`，改了哪几条」；**旧 note 留在原地不动**，两边互相链接 |
| **无关** | 不用管，但要在新 note 里写一句「已检查，无相关旧 note」 |

**部分取代为什么留在原地**：被取代的只是某几条，其余仍有效；移进 `archived/` 会让人以为整条没用了。
**完全取代时**，旧 note 移进 `archived/` 要加一行头部说明（「已被 `<新文件名>` 取代，仅作历史」），
但**正文一个字都不许改**——见下条。

## `archived/` 是冻结快照

- **只读**：不修改、不补写、不修错别字、不跟着新决定更新
- **不当现行依据**：只能当「当时是这么想的」，不能当「现在该这么做」
- **可以引用**：解释「为什么改掉旧做法」时要引它，但结论以新 note 为准

判据：**`archived/` 里的文件 mtime 变了，就是违规。**

## 文件名与目录

```
notes/
  AGENTS.md       ← 本文件，规则
  README.md       ← 给人看的索引
  proposed/       ← 方案、需求，还没落地
  implemented/    ← 已落地的决策记录
  archived/       ← 冻结，只读，不当依据
```

文件名：`YYYY-MM-DD-简短英文描述.md`，如 `2026-11-23-worktree-root-custom.md`。
日期是**写这条 note 的日期**，不是上线日期；描述用**小写英文 + 连字符**，3-6 个词说清讲什么，
不要 `notes-1.md`、不要中文名（跨平台/命令行/Git 都折腾）。

## 交叉链接

- 用相对路径：`[worktree 根目录](../implemented/2026-11-23-worktree-root-custom.md)`
- 被部分取代的旧 note 保持活跃，**新旧两边都要有指向对方的链接**
- 引用别人的关键结论时写链接，不复述——复述必然漂移

## 三条边界

- **设计规范不是 note**：`.deva/design-system.md` 是活文档，会随界面改，不在这里
- **一次性的排查记录、临时脚本、补丁包**不是 note，**也不留在仓库里**——用完即删。值得长期留的判断依据才写成 note。
- **note 不是任务列表**：待办进度在任务中心 / 提交信息里，不在 note 里维护勾选状态
